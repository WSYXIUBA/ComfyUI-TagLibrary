# 出图质量审查报告（2026-09-23）

真机出图审查 —— 前面几轮只审了功能和提示词文本，这轮第一次按"**出图**"审：
用用户真实工作流（`Anima-文生图_双采工作流.json`）批量出图，再把图变成机器可判的指标。

修法细节在 `CHANGELOG.md` 的 v1.13.1；本文只记**方法、数据、结论和未决项**。

## 方法

- **审图不用外部多模态**：`vision_analyze` 这类走外部的服务对 NSFW 直接拒绝（实测第一张
  就被拒），所以改用**本机 WD14**（`wd-eva02-large-tagger-v3`，纯本地、无内容过滤）。
  人数（`1girl`/`solo`/`2girls`/`multiple girls`）/ 背景（`simple background` vs `detailed
  background`/`scenery`）/ 取景（`close-up` vs `full body`）/ NSFW 档位都拿到了。
- **提示词侧**用同种子配对：探针按 `for seed in range(N)` 跑 2000~3000 seed，改前改后
  是**同一批种子**，差异只剩修复本身；出图侧只能独立重跑（引擎 RNG 不止吃 seed，
  PNG 里记的 seed 复现不出同一条提示词 —— 试过，43 张 0 张复现）。
- **像素侧**不依赖内容：画面外圈 8% 当背景区，算边缘密度（FIND_EDGES 均值）+ 颜色熵。
- **载荷来源**：直接从用户出图 PNG 内嵌的 `prompt`（前端 `graphToPrompt` 的真产物）扒，
  所以跑的就是他点 Queue 发出去的那张图，自定义节点的 widget 顺序不用猜。

## 未决项

- **残留 1/30 多人**：`output/TagLib复测-2026-09-23/R_用户状态_无钉选/r15_00001_.png`
  提示词是 `solo, 1girl, adult female, fairy, ... demon wings`，没有任何需搭档词。
  是模型自己多画了人，还是 WD14 把翅膀之类判成了第二个人 —— 需要人眼看一眼。
- **库内 56%（2647/4753）的词不是 danbooru 高频标签**（`tools/danbooru_audit.py`）。
  已核对过官方 API：`detailed_background` 已被 danbooru 废弃（post_count=0）、
  `studio_lighting` 压根不存在、`neon_glow`/`firelight` 是 0 贴词 —— 这些词对 booru 系
  训练的模型等于没写。Anima 有 NL 能力，所以**不能断言**它们一定降质，但人数轴上
  12 个词（`trio`/`pair`/`group`/`ot3`/`1girl and 1boy` ...）是真的在控制人数，
  单人锁会挡住它们，**关掉单人锁的群像场景就会人数失控**。
  → **已处理（v1.13.2）**：12 个人数词全部换成有贴数的真标签，出厂库/用户库/三份备份/
  规则表/代码词表全量同步，细节见 `CHANGELOG.md`。其余非人数轴的词仍待定。
- **简背景只改正面，没配负面**：简背景开着时提示词 100% 有简洁背景词，但出图只有 40%
  被判 `simple background` —— 用户工作流的负面（节点 26）是手写静态串，没有背景相关词。
  节点的第 3 个输出 `negative` 也没接上（`213[2]` 空着）。
- **`data/default/taglib/nsfw_nl.json` 是私有文件（gitignore）**：本轮在它上面修的
  两处 NL 模板（`pullses`、`gaze turns`）不在 git 里，重置扩展包会丢；引擎侧的
  "单人场景不写第二个人"过滤是代码里的，不受影响。
